### 2026-09-19 — Single-active-timer race (hardening)

The old guarantee was a `SELECT`-then-`INSERT` in `startTimer`: two requests landing in different isolates could both see no running row and both insert one. Now the database refuses the second row.

**Schema** — `db/migrations/2026-09-19-single-running-timer.sql` (also folded into `db/schema.sql` for fresh databases):

```sql
CREATE UNIQUE INDEX IF NOT EXISTS idx_entries_single_running
  ON time_entries(is_running) WHERE is_running = 1;
```

A partial index, so closed rows (`is_running = 0`) are unconstrained. The pre-check stays as a fast path for a readable error; a lost race is caught by the INSERT failing with `UNIQUE constraint failed: time_entries.is_running` and mapped to the same conflict. `stopTimer` additionally updates with `WHERE id = ? AND is_running = 1` and requires `meta.changes`, so concurrent stops cannot double-apply.

**Contract change (was 400):** `POST /api/timer/start` now returns **409** `{ error, code: "timer_running" }`; `POST /api/timer/stop` returns **404** `{ error, code: "no_active_timer" }`. MCP returns the same payloads as `result.isError` with `code`, since JSON-RPC has no HTTP status to carry.

| Check | Result |
|---|---|
| Migration on existing DB | applied clean (0 running rows at the time); duplicate detection query documented for DBs that already leaked a second timer |
| Raw SQL: second running insert | `✘ [ERROR] UNIQUE constraint failed: time_entries.is_running: SQLITE_CONSTRAINT (extended: SQLITE_CONSTRAINT_UNIQUE)` — the storage-level guarantee |
| `node scripts/check-single-timer.mjs … 20` | 20 concurrent starts → exactly one 200, 19 × 409 all with `code: timer_running`, exactly one running row; 20 concurrent stops → one 200, 19 × 404 `no_active_timer`, no running row |
| `cd worker && npm test` | 8/8 — includes the *lost-race* path (pre-check passes, INSERT throws the unique error) via a D1 stub, plus unrelated errors still propagating as 500s and a concurrent-stop losing `meta.changes` |
| REST live | start 200 → start again 409 `code: timer_running` → `{}` ids still 400 → stop 404 `code: no_active_timer` |
| MCP live | same two conflicts as `result.isError` carrying `timer_running` / `no_active_timer` |
| Double-tab UI | other tab holds the timer → clicking Start reloads and shows the winner's running timer with the notice "A timer was already running (another tab?) — refreshed from the server." |
